# IIBX Assistant

A RAG-powered chatbot for the India International Bullion Exchange, running fully locally via Ollama. No external API keys required.

---

## Architecture

```
iibx-chatbot/
├── frontend/
│   ├── iibx-chatbot.html       Chat UI
│   ├── iibx-chatbot.css        Styles
│   └── iibx-chatbot.js         All frontend logic (streaming, session, edit, retry)
├── backend/
│   ├── app.py                  FastAPI server: /api/chat, /api/health, /api/feedback
│   ├── rag.py                  ChromaDB retrieval (cosine similarity, top-k)
│   ├── ingest.py               Ingestion: PDFs + JSON scrape → chunks → embeddings → ChromaDB
│   ├── guardrails.py           Topic filter (keyword + embedding similarity + history-aware)
│   ├── system_prompt.py        IIBX system prompt + context injection
│   ├── requirements.txt
│   └── data/
│       ├── iibx_scrape.json    Auto-generated by iibx_pipeline.py — do not edit manually
│       ├── pdfs/               Downloaded PDFs (managed by iibx_pipeline.py)
│       └── feedback.json       Auto-created — stores 👍/👎 feedback logs
├── iibx_pipeline.py            Full scrape + download + ingest pipeline (run this)
└── rag_connector.py            Standalone RAG helper (reference only)
```

### Request flow

```
Browser → POST /api/chat (FastAPI)
            ↓
        Guardrail check (keyword + embedding + conversation history)
            ↓
        ChromaDB retrieval (top-6 chunks by cosine similarity)
            ↓
        System prompt augmented with retrieved context
            ↓
        Ollama (llama3 or any local model) — streamed response
            ↓
        NDJSON tokens streamed back to browser
```

The browser talks to Ollama **directly only** for the status check and model list. All chat goes through the FastAPI backend.

## Setup

### 1. Install Ollama and pull a model

```
ollama pull llama3
```

Faster alternative for CPU-only machines (recommended):
```
ollama pull llama3.2:3b
```

### 2. Create and activate the virtual environment

```
cd c:\iibx-chatbot
python -m venv .venv
.venv\Scripts\activate
```

### 3. Install dependencies

```
pip install -r backend/requirements.txt
pip install requests beautifulsoup4 pymupdf
```

### 4. Run the data pipeline

This scrapes all IIBX pages, downloads PDFs, and builds the vector store:

```
python iibx_pipeline.py
```

Takes a few minutes on first run. Re-run whenever IIBX publishes new content.

### 5. Start the backend

```
cd backend
uvicorn app:app --reload --port 8000
```

### 6. Start Ollama

```
ollama serve
```

### 7. Open the frontend

Serve `frontend/` via Live Server (VS Code) or any static server on port 5500, then open `http://localhost:5500/iibx-chatbot.html`.

```
cd C:\iibx-chatbot\frontend
python -m http.server 5500
```

## Data pipeline

`iibx_pipeline.py` does three things in sequence:

1. **Scrapes HTML content** from all IIBX pages listed in `CONTENT_URLS` — including every contract spec page and writes `backend/data/iibx_scrape.json`. This file is fully regenerated each run; do not edit it manually.
2. **Downloads PDFs** from `iibx.co.in` into `backend/data/pdfs/`. Already-downloaded files are skipped.
3. **Runs `ingest.py`** which chunks everything (800 chars, 120 overlap), embeds with `all-MiniLM-L6-v2` locally, and stores in ChromaDB.

To add a new page to the knowledge base, add its URL to `CONTENT_URLS` in `iibx_pipeline.py` and re-run.

## Features

### RAG pipeline
Retrieves the top-6 most relevant chunks from ChromaDB by cosine similarity and injects them into the system prompt before calling the LLM. Source type is tracked per chunk (`pdf` or `web`) and shown in citations.

### Guardrails
Three-layer topic filter in `guardrails.py`:
- **Layer 0** — Conversation history check: short follow-up messages mid-conversation pass through automatically (handles "explain that", "one sentence", etc.)
- **Layer 1** — Fast keyword match against an IIBX/bullion vocabulary
- **Layer 2** — Embedding cosine-similarity fallback against domain anchor sentences

Off-topic queries are blocked before Ollama is ever called.

### Session persistence
Conversation is saved to `localStorage` after every AI response. On page load, if a saved session exists, a banner offers to restore it. Discarding or clearing chat removes the saved session.

### Retry
Each AI response has a ↺ retry button (latest response only). Clicking it removes the old answer, re-sends the same question, and streams a fresh response in place, correctly positioned even if later messages exist below it.

### Edit last question
The most recent user message has a ✏️ button (visible on hover). Clicking it makes the bubble editable. Confirming removes that message and everything after it from history and the DOM, then re-sends the edited question.

### Re-ask on stop
If generation is stopped before any response arrives, a ↺ Re-ask button appears on the user bubble. Clicking it removes the orphaned bubble and re-sends the question cleanly.

### Source citations
Each response shows the source documents and sections used, with 📄 for PDFs and 🌐 for web pages.

### Feedback
👍/👎 buttons on each response POST to `/api/feedback`, which appends `{query, response, rating, sources, timestamp}` to `backend/data/feedback.json`.

### Copy answer
⎘ button copies the raw response text to clipboard, briefly showing ✓ to confirm.

### Chat export
Downloads the full conversation as a timestamped `.txt` file with timestamps, roles, and source citations.

## Performance note

On CPU-only machines (no NVIDIA GPU), `llama3` 8B is slow — expect 30–60s per response. Switching to `llama3.2:3b` gives roughly 3× faster responses with minimal quality loss for Q&A tasks. Select the model from the dropdown in the UI after pulling it.
